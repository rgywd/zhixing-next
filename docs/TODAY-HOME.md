# 今天：首页与手机信息

当前源码按首页参考图重构“今天”：位置天气栏、今日节律建议、下一项日程、财务和健康速览、直接记开销、固定常用与最近动态。首页数值取实际服务记录，未设置预算或未读取记录时保持未知；不从漏记计算饮食达标率，也不预设步数目标。

本次属于 0.2.1 之后的首页改动；已发布的 v0.2.1 APK 不包含此页，安装时应使用本次任务交付的首页预览包，或后续明确列入此改动的正式版本。

## 从首页使用

- 点击顶端位置天气栏打开“今日信息”。位置天气与日历分别按需启用，不在首次启动时连续弹权限。
- 位置天气启用后，首页在前台更新区域和天气；位置由系统 GPS、Wi-Fi、基站融合，允许大概位置。可单独请求开启系统网络辅助定位；拒绝后仍可尝试 GPS，不显示虚构的“Wi-Fi 定位成功”。不扫描 SSID/BSSID，不申请附近 Wi-Fi、后台定位或定位前台服务权限。
- 天气通过 HTTPS 向 Open-Meteo 查询，只发送保留两位小数的经纬度，不带知行令牌。天气为模型当前天气数据，展示来源和数据时间；无有效定位或天气请求失败时明确显示未知／失败。反向地理编码失败只显示“当前位置”。
- 日历只读取并展示今天的日程，过滤取消／本人拒绝的活动，展示正在进行或下一项定时日程，再考虑全天活动。点击打开系统日历查看，不自动创建或修改日程。
- 时间和日期跟随手机时钟及当前时区，无需额外系统授权。跨日会重新读取当天记录与日程；已启用的定位天气按 15 分钟节流，日历按 1 分钟节流。
- “开始”和“梳理乱序思路”把输入与已读取的今日信息追加到原主 Agent 草稿，可修改后自行发送；不自动创建会话或提交消息，也不覆盖原草稿。分享的地点是地区名称，不附精确坐标。
- “记一笔开销”直接进入财务手工记录；已有未完成草稿继续保留。财务和健康仍属于生活子页，返回生活。

## 授权与本机状态

Android 只申请使用时定位和 `READ_CALENDAR`；`WRITE_CALENDAR` 继续在生成 manifest 中阻止。SDK 57 的日历权限函数会同时要求读写，因此 Android 采用 React Native 的只读权限请求，再使用新的 Calendar 读取 API。原设置页的系统日历编辑器继续使用显式 legacy 入口，无需本 App 获得写权限。

iOS 配置日历 full access 的读取用途说明（系统权限粒度），代码只调用读取；本次原生验收目标仍是 Android 模拟器，iOS 另列实际验证边界。

开关仅保存在本机。坐标、天气和日程只保留在会话内存，离开首页或进入后台取消定位／天气请求并忽略迟到结果；关闭开关或权限撤回后清除相应信息。不会自动上传这些资料；用户从首页开始后，今日概况进入可编辑的聊天草稿，只有用户自行发送才分享给服务。系统定位及反向地理编码由操作系统处理。

读取开关失败时提供重试，不用默认值覆盖原设置；权限拒绝不反复自动申请，可手动重试或打开系统设置。时间与天气没有单独的系统“权限”；天气使用网络及用户选择的位置。

## 实现与验证

- `TodayHomeView.tsx` 负责参考图布局，复用共享主题尺度；`OverviewPanels.HomePanel` 保留常用、最近和资源操作。
- `TodayHomePanel.tsx` 组合手机与服务数据、权限操作和可编辑草稿交接。
- `useTodayDeviceContext.ts` 管理本机会话状态与取消，`todayLocation.ts`／`todayCalendar.ts` 接入原生能力，`todayWeather.ts` 校验天气数据，`todayHomeLogic.ts` 负责真实摘要和时间边界。
- `useTodayServices.ts` 按手机当地日期读取财务月度及健康当日汇总，换连接／跨日／卸载后忽略旧请求，不把昨天的健康记录当成今天。

交付需通过移动端门禁、两平台 JS bundle、权限 manifest 检查和 Android 模拟器实际授权／拒绝、日历读取、定位取消及截图验收。模拟定位只能证明模拟器接口链路，不证明实体设备 GPS 或 Wi-Fi 信号质量；实时天气需在目标网络实际请求成功后才列为通过。
