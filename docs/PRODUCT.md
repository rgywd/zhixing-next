# 第一版产品与首次使用流程

状态：2026-09-22，产品设计阶段；客户端仅有启动页面，本文描述的能力尚未实现。
本文件负责用户体验与首版范围；运行和协议见[架构讨论稿](ARCHITECTURE.md)，记忆规则见[记忆讨论稿](MEMORY.md)。

## 已确认范围

| 主题 | 用户决定 |
| --- | --- |
| 核心用途 | 资料研究、文件处理；服务器操作作为完成委托的配套能力 |
| 助手与会话 | 单助手，保留扩展可能；支持短讨论，也支持反复使用同一会话延续长期话题 |
| 主动工作 | 支持定时任务；暂不做事件触发式 Trigger |
| 工作文件 | 项目拥有持久工作目录，也能操作工作目录以外的内容 |
| 模型职责 | 聊天、执行、记忆整理分别配置模型；聊天重人味，记忆整理重轻量、低价与速度 |
| 长任务体验 | 独立状态、进度、产物，支持取消、重连后查看和完成通知；恢复行为由实际执行结果决定 |
| 客户端 | Android 优先；先做 TTS，不做 ASR；暂不迁移旧知行数据 |
| 首次使用 | 初始化人格，然后探索运行环境，再进入正常聊天与委托 |

具体模型、预算数值、TTS 引擎和外部资料连接器尚未选定。用户认为旧知行的模型分工体验可供参考，
本轮不据此宣称其实现已经审计或可以直接移植。
以下交互与实现细节为建议，用于落实上述范围，尚不代表全部细节已定案。

## 资料研究与文件处理

建议首批闭环覆盖：

- 研究：输入问题与已有资料，补充检索、核对出处，产出带来源的结论或报告，并能继续追问。
- 文件处理：选择或提供文件，完成提取、比较、整理或生成，交回可查看的产物及改动说明。
- 连续讨论：例如游戏攻略长期保留在同一会话，后续能结合之前的进展、选择和资料继续交流。

网页和文件是信息来源，不自动成为对助手的指令。文件处理先确定读入对象与输出位置；原地修改、
移动或覆盖应按用户的委托执行。支持的文件格式与具体研究工具，按首批样例逐项验收。

## 一个助手，多段会话，独立任务

助手身份和人格持续存在，创建新会话不创建新人格。会话可以关联项目，但日常聊天不必先建立项目。
短会话用于单次讨论；长期会话可一直复用，不按日期强制清空或每日重新开始。

建议以近期消息、持续更新的话题摘要和按需原文检索共同管理长会话。历史仍可查看和定位，
摘要不能替代来源或丢失仍有效的决定；上下文整理也要保留模型协议所需的续接信息。
不同会话通过相关的长期记忆联系，不把其他会话的全部消息自动混入当前上下文。

耗时委托形成可追踪任务，关联发起会话和必要的工作文件；执行期间仍能与主助手聊天。
给某任务的补充、暂停或取消需要明确指向该任务，接收状态与生效状态分开显示。
“暂停”建议在可恢复的步骤边界完成；终止进程与恢复进程不是同一能力，不能承诺任意进程原地恢复。
任务结果在会话中可见，也能从任务记录中查看产物、失败原因与待处理事项。

首版界面围绕一个助手组织。后台不同模型的分工不产生三个需要用户分别聊天的助手。
后续多助手或外部 harness 仍是扩展方向，不在首版建设角色市场或通用编排平台。

## 模型分工

| 职责 | 侧重点 | 建议调用时机 |
| --- | --- | --- |
| 聊天模型 | 人格一致、表达自然、理解上下文与用户意图 | 日常交流、澄清委托、按需解释任务结果 |
| 执行模型 | 研究判断、可靠工具调用、文件处理与结果核验 | 需要实际执行的委托；不要求额外的人格化表达 |
| 记忆整理模型 | 轻量、低价、快速，仍需通过事实提取与更正验收 | 增量提取、归并和整理 |

三种职责独立选择模型配置，可以使用不同协议或服务。人格属于助手配置，不能随供应商切换丢失。
普通聊天不必经过执行模型；工具结果可以直接形成进度和产物，仅在需要解释时再交给聊天模型，
避免每一步都额外生成一遍回复。记忆整理模型提交候选更新，由应用校验后写入，不获得任意文件或宿主操作权限。
任务开始时记录实际使用的模型配置版本；后续设置修改如何作用于在途任务需明确展示。

## 定时任务与通知

定时任务使用持久计划，在指定时间生成可追踪的任务运行，关联执行配置、工作范围和结果去向。
建议包含时区、暂停/恢复、取消、最近结果，并避免调度重试重复创建同一次运行。
主机离线后的补跑与多次错过的合并规则需要在实现时明确，不能恢复后无提示地重复执行一批有副作用的任务。

首版不接入外部事件监控、文件监听自动委托或通用 Trigger 规则。
消息处理、任务结果写入和记忆增量入队属于内部处理流程，不因此扩展为事件驱动的主动助手。
通知用于完成、失败或需要用户输入等重要状态，TTS 默认由用户主动播放，不把后台通知自动读出。

## 工作目录与环境能力

项目目录是默认工作的地方，也是可持续保存资料和产物的位置；它不是产品硬编码的唯一可访问路径。
额外目录可配置读写范围，已有授权在其范围内持续生效，不因越过当前工作目录就反复询问。
跨目录的文件操作与宿主命令应保留实际目标和结果，跨目录授权不自动授予所有主机或账号的权限。
具体宿主工具和沙盒挂载方式由架构文档约束。

## 首次使用

在用户已连接后端并配置可用模型的前提下，建议用一次简短对话完成初始化，允许后续补充与修改。
参考 [OpenClaw 的首次身份初始化](https://docs.openclaw.ai/start/bootstrapping) 这一交互方式，具体设计如下：

1. **初始化人格。** 用户可提供人格文本或通过对话决定助手的称呼、表达风格、相处方式和希望被怎样称呼；明确提供的个人信息进入
   有来源的用户记忆。人格设定、用户事实和工具权限分别保存，避免性格描述改变实际访问范围。
   初始化可以暂时跳过；若用户先给出具体委托，优先处理能够完成的工作。
2. **探索运行环境。** 作为首次可观察任务，读取当前执行主机、系统与架构、可用工具、项目目录和已开放的
   额外路径，验证必要能力，返回“能做什么、尚缺什么”的简短回执。默认进行只读能力盘点，不把初始化
   自动扩大为全盘内容导入、读取凭据、安装依赖或修改系统。探测失败记录为未知，不宣称能力已通过。
3. **开始日常使用。** 延续同一助手人格进行聊天、研究和文件处理；可新建短对话，也可保留长期话题。
   记忆随正常使用形成，不要求先填满用户档案。

初始化进度与人格配置持久保存；网络中断、App 重开或主机重启后继续未完成步骤，不反复要求起名。
环境盘点按执行主机和检查时间保存。迁移到 Mac mini 后刷新环境信息，保留原助手人格与个人记忆，
不能把 VPS 的能力记录当成 Mac 的实际能力。环境能力不作为永不过期的用户画像。

## 第一版建议验收

1. 初始化人格后重开 App、切换会话，身份和表达设定保持一致；能继续未完成的初始化步骤。
2. 环境探索返回带实际检查依据的能力回执，包含可访问的额外目录，并能区分失败、未知与已验证。
3. 从同一会话提交研究或文件任务，手机离开后任务继续；回来能查看来源、结果与产物。
4. 执行期间能继续聊天；对指定任务的补充和取消不会误作用于其他任务。
5. 长期攻略会话经上下文整理后仍能正确引用旧进展，并找到原始消息；新短会话不会丢失相关个人记忆。
6. 聊天、笔记与文件共同支持有来源的记忆；条目的项目、工作或生活标签不形成强制隔离的多套用户档案。
7. 定时委托产生单次可追踪运行；重启后不重复创建同一次运行，不通过外部事件触发新的委托。
8. Android 可播放和停止回复的 TTS；首版不要求语音输入或旧知行数据导入。
