# 第一版产品与首次使用流程

状态：2026-09-29，五入口、子智能体、后端轻量记忆、图片输入、资源库查看下载及主知行隔离执行已实现。截图到模型和财务工具的本地链路已验证，真实云模型识别质量与真机仍待验收；真实账户、自动对账、资源收藏/删除及置顶对话尚未实现。执行启用与验收见 [HARNESS-UPGRADE.md](HARNESS-UPGRADE.md)。
本文包含尚未实现的首版目标；当前实际能力与限制见[后端说明](../backend/README.md)。
本文件负责用户体验与首版范围；运行和协议见[架构讨论稿](ARCHITECTURE.md)，记忆规则见[记忆讨论稿](MEMORY.md)。

## 产品原则

用户可以直接说、发截图或操作服务，知行负责理解、整理和完成。不要把找原话、逐项对账、确认每条提取结果、维护过期状态变成日常使用步骤。清楚的信息直接处理；只有金额、对象或行动方向不明且会影响结果时才追问。

内部可以保留必要的来源与执行回执供纠错，但默认界面只呈现用户关心的现状、结果和下一步。用户一句自然语言纠正应能改正错误。安全权限和实际任务回执仍由程序保证，不能因为交互轻便就猜测金额、伪造完成或扩大工具权限。

## 已确认范围

| 主题 | 用户决定 |
| --- | --- |
| 核心用途 | 资料研究、文件处理；服务器操作作为完成委托的配套能力 |
| 助手与会话 | 单助手，保留扩展可能；支持短讨论，也支持反复使用同一会话延续长期话题 |
| 运行中输入 | 区分 Queue 排队与 Steer 引导两种意图 |
| 主动工作 | 支持定时任务；暂不做事件触发式 Trigger |
| 工作文件 | 项目拥有持久工作目录，也能操作工作目录以外的内容 |
| 模型职责 | 聊天、执行、记忆整理分别配置模型；聊天重人味，记忆整理重轻量、低价与速度 |
| 长任务体验 | 独立状态、进度、产物，支持取消、重连后查看和完成通知；恢复行为由实际执行结果决定 |
| 客户端 | Android 优先；先做 TTS，不做 ASR；暂不迁移旧知行数据 |
| 首次使用 | 初始化人格，然后探索运行环境，再进入正常聊天与委托 |
| 手机入口 | 底部为首页、生活、AI、工作、设置；首页默认进入，首版保持样板房 |
| 服务与智能体 | 主知行是默认对话入口；服务可以配置专用子智能体，也允许用户在服务内直接与其细聊 |
| 首个生活服务 | 财务总览：通过截图和对话了解各平台余额、收支与具体扣费问题，不要求用户逐笔对账 |
| 资源 | 上传图片、生成图片与文件产物进入设置中的统一资源库；财务原图默认保留，可清理 |

具体模型、预算数值、TTS 引擎和外部资料连接器尚未选定。新知行独立实现；少数旧服务只有在真实需求出现时才单独接入。
以下交互与实现细节为建议，用于落实上述范围，尚不代表全部细节已定案。

## 五个入口与服务

| 入口 | 定位 |
| --- | --- |
| 首页 | 默认进入；先留作样板房，等真实服务形成后再定内容 |
| 生活 | 生活服务及其速览；首个服务是财务管理 |
| AI | 中间的主知行入口，承载日常聊天与任务委托 |
| 工作 | 置顶聊天、项目和任务的入口；后续可连接现有 Work 服务，重新设计界面，不迁移旧 UI 或数据模型 |
| 设置 | 分组管理模型供应商、默认模型、搜索服务、人格偏好、子智能体、资源库与服务连接 |

当前 AI 入口作为沉浸式独立页面隐藏底部五入口，通过顶部关闭按钮或 Android 返回键回到进入前的页面；先显示欢迎页、建议提问和聊天/任务输入框，发送首条消息或选择文件时才创建会话。左侧栏集中展示搜索、记忆和按时间排列的对话历史，并可返回欢迎页新建对话。侧栏搜索由服务端检索全部会话的标题与消息正文，支持以空格分隔关键词并按相关度或时间排序；结果显示命中片段，点开后定位到消息。记忆以紧凑列表供查看和忘记，整理仍由后台完成。整体界面支持跟随系统、白天与夜间，配色与共享控件见 [共享 UI](UI.md)。

底部导航仅在首页、生活、工作和设置的主页面显示，以悬浮胶囊覆盖在内容上；中间的 AI 按钮略微凸起，以中心放射图标呈现，两侧通过圆滑凹槽衔接底栏，滚动末尾留出导航避让空间。财务、定时计划、助手管理、模型与设置等子页面隐藏底栏，也不保留底栏留白；可通过页内返回入口或 Android 返回键回到所属主页面，键盘打开时先收起键盘。主 AI 页面继续保持无底栏的沉浸布局。

这些页面展示同一助手、任务和资料的不同视图，不为生活与工作建立两份用户身份或记忆。服务本身可直接使用；每项服务可以预留一个固定、可编辑、可隐藏或暂不配置的专用子智能体位置。专用子智能体只使用该服务授权的工具，主知行可以委托它，用户也可以在服务内直接交谈。用户自建子智能体可增删；不因此提前开发角色市场或跨 harness 编排器。

当前手机已接通首页最近对话、AI 真实会话、工作页最近对话、项目创建与定时计划、设置助手管理、供应商模型目录及连接设置。底部五入口使用图标与文字，工作页直接打开已有对话、创建持久项目或管理定时计划；置顶对话尚未实现。未连接时也能看到五入口，设置中的服务连接和 AI 页均可连接；没有“退出预览”模式。五入口不常驻品牌和在线状态栏，异常时才显示连接或执行提示。主知行会话页采用助手与当前话题标题、完整消息区和底部一体化输入面板；用户消息保留气泡，知行回复直接排版 Markdown 正文，输入工具保持在可横向滚动的工具栏中；运行中才额外显示进度及 Queue / Steer，任务记录仍可从消息打开。主知行可切换当前对话后续聊天使用的模型与思考深度，为任务单独选择模型和思考深度，并在欢迎页或对话中配置、开启联网搜索及上传文件；设置可设置聊天/执行/记忆整理的默认模型。模型供应商密钥仍留在服务器；搜索服务密钥由手机提交后保存在服务器。生活页进入财务子页面，在账户与收支速览下使用简约对话窗口，不跳转到主 AI 聊天页。财务助手可从用户文字或通过视觉模型读取截图中清晰可见的金额，展示最新平台余额观察值和最近收支记录；不能直接读取账户，不自动推算总资产。页面细节仍可调整。

### 生活页首个服务：财务

生活页使用暖白与红色的生活场景头图、财务卡片、四项生活话题入口和页脚插画。账户一览、收支变化、税务问题与理财建议均进入现有财务子页面；有真实记录时，卡片额外显示最近的余额与收支，不生成示例金额。购物、出行、健康和家居入口会在沉浸式 AI 欢迎页填入可编辑的问题，由用户补充后发送；已有输入会保留，关闭 AI 后返回生活页。

用户的资金与消费散布在工资卡、支付宝、微信、微众银行、东方财富、公积金及购物平台等处。财务页先让用户方便地看到自己提供的各平台余额和收支，并能向财务子智能体追问某笔扣费的实际顺序。不同平台是否有可用接口留待具体接入时判断，首条链路以截图为主。

用户发截图或说一句话，由多模态模型直接整理可见信息；不另建 OCR 服务或强制逐条核对流程。平台之间的扣费关系只在具体问题需要时分析，不要求用户为每笔消费维护一张支付路径图，也不设置余额“过期”管理制度。看不清的金额和无法确定的扣款环节不猜测，必要时简短追问。财务原始截图保留供以后查看或清理，整理结果可用自然语言纠正。

当前财务页复用会话附件上传、预览与下载，财务助手可读取本会话工作目录中的文本、PDF 与 Word 文本，并使用已声明图片输入能力的模型理解附件图片；不继承主助手的额外目录授权，也不获得物理文件写入或委派能力。PDF/Word 的文本提取不包含嵌入图片或 OCR。联网仅在发送时明确选择搜索服务后开放。

### 设置中的资源库

新知行接收和生成的图片统一成为可管理资源，普通上传文件与任务产物也沿用同一个入口。当前资源库提供分页查看、按已加载名称筛选、图片预览和下载分享；全库搜索、收藏、整理和删除为后续目标。产品方向是财务截图与其他图片一样直接显示缩略图，不默认模糊或二次解锁。聊天、财务记录和任务引用资源，不为了不同页面复制文件。原图默认保留；后续清理功能应在删除被引用的原图时说明影响，已整理的文字记录不随图一起消失。手机版式独立设计，不照搬桌面资源库截图。

## 资料研究与文件处理

建议首批闭环覆盖：

- 研究：输入问题与已有资料，补充检索、核对出处，产出带来源的结论或报告，并能继续追问。
- 文件处理：选择或提供文件，完成提取、比较、整理或生成，交回可查看的产物及改动说明。
- 连续讨论：例如游戏攻略长期保留在同一会话，后续能结合之前的进展、选择和资料继续交流。

网页和文件是信息来源，不自动成为对助手的指令。知行根据请求选择读入对象与输出位置；只有目标不明或要覆盖重要原件时才追问。支持的文件格式与具体研究工具，按真实样例逐项验收。

## 一个助手，多段会话，独立任务

助手身份和人格持续存在，创建新会话不创建新人格。会话可以关联项目，但日常聊天不必先建立项目。
短会话用于单次讨论；长期会话可一直复用，不按日期强制清空或每日重新开始。

建议以近期消息、话题摘要和按需历史检索共同管理长会话。用户可查看历史，也能直接问知行过去讨论的结论，不要求自己定位原文；上下文整理不能丢失仍有效的决定或模型协议所需的续接信息。
不同会话通过相关的长期记忆联系，不把其他会话的全部消息自动混入当前上下文。

耗时委托形成可追踪任务，关联发起会话和必要的工作文件；执行期间可以继续发送消息，按下述 Queue / Steer 语义处理。
另开会话讨论其他话题时使用该会话的上下文，不自动引导原任务。
“暂停”建议在可恢复的步骤边界完成；终止进程与恢复进程不是同一能力，不能承诺任意进程原地恢复。
任务结果在会话中可见，也能从任务记录中查看产物、失败原因与待处理事项。

当前实现会在重启后继续带恢复记录的原任务，先核对已完成步骤。需要替换外部原件、首次进行未持久授权的联网执行，或中断步骤结果不明时，在会话和任务详情展示具体操作决定；普通工作目录内的操作继续自主执行。批准与恢复的实际边界见[中断恢复与授权](RECOVERY-AND-AUTHORIZATION.md)。

AI 入口默认与主知行聊天。后台模型分工不产生三个需要用户分别管理的助手；专用服务子智能体可在对应服务内直接交谈，主知行也能委派已配置助手。财务记录由专用工具写入同一 SQLite 数据，主知行通过委派可查询；不能把文字观察值误写成已核实账户余额。外部 harness 编排仍是后续扩展，不在首版建设角色市场或通用编排平台。

### Queue 与 Steer

以下细节为建议；两种发送意图由用户明确选择，输入框显示当前模式与目标，不依赖模型猜测来替换用户选择。

| 模式 | 意图与时机 | 示例 |
| --- | --- | --- |
| Queue：排队发送 | 保留当前运行；该轮完整执行（包括工具循环）结束后，按提交顺序处理后续输入 | “这份报告完成后，再生成一份对照表” |
| Steer：引导当前任务 | 把补充、限制或方向修正送给指定的当前运行，在下一个可调整的步骤生效 | “研究范围改为近三年，重点比较价格” |

建议忙碌时默认 Queue，可切换 Steer；未开始处理的排队消息可以撤回或编辑。空闲时普通发送直接开始新一轮。
Queue 属于当前会话或明确指定的任务后续输入，不建立一条混合所有会话的全局聊天队列。
当前运行暂停、等待用户输入或失败时，排队消息保持待处理；取消当前运行也不清空它们，是否继续可单独操作。

Steer 保留用户原文，展示“已接收、待应用、已应用”及对应目标。“已应用”表示进入后续决策上下文，
不表示修改目标已完成；在途工具可能仍需结束或明确中断，已经发生的文件或外部操作不会被自动撤销。
目标运行若在投递前已结束，明确返回未应用，允许改为后续消息；不能悄悄引导下一任务。

取消和暂停使用独立任务控制入口，直接作用于指定运行，不排在普通消息后面，也不依赖模型阅读到一条 Steer 才停止。
手机断线、重试或服务器重启后，队列顺序、待应用引导与处理回执应可恢复，不因重复提交多执行一次。

## 模型分工

| 职责 | 侧重点 | 建议调用时机 |
| --- | --- | --- |
| 聊天模型 | 人格一致、表达自然、理解上下文与用户意图 | 日常交流、澄清委托、按需解释任务结果 |
| 执行模型 | 研究判断、可靠工具调用、文件处理与结果核验 | 需要实际执行的委托；不要求额外的人格化表达 |
| 记忆整理模型 | 轻量、低价、快速，仍需通过事实提取与更正验收 | 增量提取、归并和整理 |

三种职责独立选择模型配置，可以使用不同协议或服务。人格属于助手配置，不能随供应商切换丢失。
普通聊天不必经过执行模型；工具结果可以直接形成进度和产物，仅在需要解释时再交给聊天模型，
避免每一步都额外生成一遍回复。记忆整理模型提交候选更新，由应用校验后写入，不获得任意文件或宿主操作权限。
模型目录按供应商分组，可搜索和收藏；主知行、财务及其他专用助手的直接对话显示当前模型，并可为后续聊天选择模型与思考深度。任务默认使用独立执行模型，也可在发送前单独选择；聊天和任务都可以为本次发送选择联网搜索服务。模型与联网选择不改变会话绑定的助手身份；单次模型选择优先于会话选择，再继承助手配置或角色默认模型。手机设置支持供应商与模型管理，密钥仅保存在服务端。输入入队时固化模型、协议、地址、参数和私有凭据，之后修改配置不追改已入队输入；管理流程与 v10 升级见[供应商与模型管理](PROVIDER-MANAGEMENT.md)。

## 定时任务与通知

定时任务使用持久计划，在指定时间生成可追踪的任务运行，关联执行配置、工作范围和结果去向。
建议包含时区、暂停/恢复、取消、最近结果，并避免调度重试重复创建同一次运行。
主机离线后的补跑与多次错过的合并规则需要在实现时明确，不能恢复后无提示地重复执行一批有副作用的任务。

首版不接入外部事件监控、文件监听自动委托或通用 Trigger 规则。
消息处理、任务结果写入和记忆增量入队属于内部处理流程，不因此扩展为事件驱动的主动助手。
通知用于完成、失败或需要用户输入等重要状态，TTS 默认由用户主动播放，不把后台通知自动读出。

手机设置的“手机能力”按需接入安卓通知、系统日历与一次定位。当前通知支持授权与本机测试；
App 关闭后的服务器任务结果通知尚未接入。定时计划可以把本次时间带入系统日历，由用户保存，
不读取全部日程或反向修改知行计划。位置先在手机显示，用户带入对话并发送后才交给服务。
权限拒绝不阻止其他操作，详细行为见[安卓手机能力](ANDROID-CAPABILITIES.md)。

## 工作目录与环境能力

项目目录是默认工作的地方，也是可持续保存资料和产物的位置；它不是产品硬编码的唯一可访问路径。
额外目录可配置读写范围，已有授权在其范围内持续生效，不因越过当前工作目录就反复询问。
跨目录的文件操作与宿主命令应保留实际目标和结果，跨目录授权不自动授予所有主机或账号的权限。
具体宿主工具和沙盒挂载方式由架构文档约束。

## 首次使用

在用户已连接后端并配置可用模型的前提下，建议用一次简短对话完成初始化，允许后续补充与修改。
参考 [OpenClaw 的首次身份初始化](https://docs.openclaw.ai/start/bootstrapping) 这一交互方式，具体设计如下：

1. **初始化人格。** 用户可提供人格文本或通过对话决定助手的称呼、表达风格、相处方式和希望被怎样称呼；有用的个人信息随正常交流形成记忆，不要求用户提供原话或逐条确认。人格设定、用户事实和工具权限分别保存，避免性格描述改变实际访问范围。
   初始化可以暂时跳过；若用户先给出具体委托，优先处理能够完成的工作。
2. **探索运行环境。** 作为首次可观察任务，读取当前执行主机、系统与架构、可用工具、项目目录和已开放的
   额外路径，验证必要能力，返回“能做什么、尚缺什么”的简短回执。默认进行只读能力盘点，不把初始化
   自动扩大为全盘内容导入、读取凭据、安装依赖或修改系统。探测失败记录为未知，不宣称能力已通过。
3. **开始日常使用。** 延续同一助手人格进行聊天、研究和文件处理；可新建短对话，也可保留长期话题。
   记忆随正常使用形成，不要求先填满用户档案。

初始化进度与人格配置持久保存；网络中断、App 重开或主机重启后继续未完成步骤，不反复要求起名。
环境盘点按执行主机和检查时间保存。迁移到 Mac mini 后刷新环境信息，保留原助手人格与个人记忆，
不能把 VPS 的能力记录当成 Mac 的实际能力。环境能力不作为永不过期的用户画像。

## 第一版建议验收

1. 初始化人格后重开 App、切换会话，身份和表达设定保持一致；能继续未完成的初始化步骤。
2. 环境探索返回带实际检查依据的能力回执，包含可访问的额外目录，并能区分失败、未知与已验证。
3. 从同一会话提交研究或文件任务，手机离开后任务继续；回来能查看来源、结果与产物。
4. 执行期间 Queue 按顺序在该轮结束后处理，Steer 在运行中改变后续方向；接收与应用回执明确。
5. 长期攻略会话经上下文整理后仍能正确引用旧进展，并找到原始消息；新短会话不会丢失相关个人记忆。
6. 聊天、笔记与文件共同支持记忆；用户一句话可以纠正错误，不需要找回原文；工作与生活不形成两套用户档案。
7. 定时委托产生单次可追踪运行；重启后不重复创建同一次运行，不通过外部事件触发新的委托。
8. Android 可播放和停止回复的 TTS；首版不要求语音输入或旧知行数据导入。
9. 引导与运行结束同时发生时不误投到下一任务；取消不被排队消息阻挡，也不丢弃未处理输入。
10. 消息重试、断线和进程重启后不重复消费 Queue / Steer，不重复执行已经发生的工具副作用。
11. 用户发送财务截图后，能在财务页看到简明整理结果，并在服务对话中追问扣费；无法识别的金额不被编造，用户无须逐笔对账。
12. 上传和生成的图片可从设置资源库再次找到；财务原图直接预览、可清理，删除原图不误删已整理的记录。
