基于 `79bc0d1`，实施顺序见 [计划](AGENT-HARNESS-PLAN.md)。以下为当次本地验收结果；在该验收时尚未部署生产，也未发布原生安装包。后续 2026-09-30 生产部署与验收摘要见[部署说明](DEPLOYMENT.md)，不改写本次测试的历史范围。

## 行为变化

| 场景 | 当前行为 |
| --- | --- |
| 模型短暂失联、限流、5xx | 仅重试模型请求，最多 3 次，指数退避并尊重有上限的 Retry-After；鉴权和请求错误不重试。等待可被取消或新指令打断 |
| 反复使用同一工具和参数 | 连续第 4 个不同调用停止；同一步骤的 checkpoint 恢复不重复计入死循环；进程轮询由总调用预算约束 |
| 长任务完成 | 声明完成条件后，未验证条件拦截最终答复。检查使用真实命令或成功操作回执；有阻碍时明确记为部分完成/失败 |
| 后台命令 | 最多 4 个并行进程，支持启动、读取、短等待和停止。输出有界、可查退出码；超时停止进程组，任务退出停止容器 |
| 缺必要信息 | App 问题卡暂停，问题和回答写入 SQLite。恢复读取认证接口保存的回答，不信任 graph resume 中的答案 |
| 历史和资料 | 主助手搜索本人历史、分段读原消息、查找保存的资源并校验哈希后读取文本；历史不构成新指令 |
| GitLab | 指定项目的项目/议题读取、搜索、分页；可选创建/更新议题。写入先在 App 批准主机、项目和参数；超时结果不明时进入核对决定，不自动重发 |
| 子助手和技能 | App 可选子助手模型，入队时保存私有模型快照，主/子助手共用预算。自定义技能复制成内容哈希快照后只读挂载 |
| 任务记录 | 显示完成条件、检查类型、累计调用和供应商报告的 token；缺失用量明确标示，不换算成虚构费用 |

非零退出码现在记为失败回执，不能因为 SDK 成功传回输出就记成执行成功。实际使用发现宿主路径与容器路径容易混淆：文件工具现接受 `/workspace` 别名，执行任务的文件元数据返回容器路径；文件正文不做字符串替换。

## 配置与升级

参照 [配置示例](../backend/config.example.toml)：`[limits]` 配置调用/token/时间预算；`[gitlab]` 配置 `url`、`token_env`、`projects` 和 `allow_writes`。凭据只放服务端环境；默认只读，开启写权限后仍逐操作批准。HTTP 客户端不跟随重定向，不接受模型指定主机。

在 `[execution]` 设置 `skills_dir = "./skills"`，目录为 `<技能名>/SKILL.md`；禁止符号链接，最多 300 文件、单文件 1 MiB、合计 10 MiB。在 `/custom-skills/` 只读挂载；恢复时技能指纹改变会拒绝重放。

`context_window` 可在模型高级设置或模型 API 配置，应填写供应商实际容量；通过 SDK profile 驱动自动压缩。TOML 模型仅初次导入生效，现有安装使用模型管理更新。

数据库 v10 → v11 新增任务条件、问题、用量、进程、子助手模型快照。升级前完成或取消旧版在途任务，停 API/worker 并备份完整数据目录及配置，构建新版 Docker 镜像，再同时启动新版服务。跨版本 checkpoint 不承诺直接续跑，可核对原回执后发新要求。回滚须恢复配套旧数据备份，不能只把旧程序指向 v11 数据库。

## 能力边界

- 完成条件和证据不能证明任意任务的语义、审美或事实完全正确。`agent_review` 是模型核对回执，`command` 是实际命令断言，任务详情明确区分。
- 后台进程不跨容器存活，不提供 PTY/交互终端；恢复后须核对文件再决定重启。
- token 限额按已报告用量阻止下一次调用，无法撤回在途请求或推断缺失消耗。统计覆盖主/子助手循环，不含独立记忆整理及 SDK 内部压缩请求。
- 历史/资源读取仅提供给单用户主助手；图片/OCR 与复杂格式由已有视觉/执行链路处理。
- GitLab 更新核对 `updated_at`，但 REST 接口没有原子比较后写入，仍存在短暂并发编辑窗口。OAuth、通用 MCP、评论/合并/仓库写入不在本轮范围。
- 本次本地核验时生产仍为 `093cc305`，API/worker 正常，本轮未改动生产。JS bundle 不等于 APK、iOS 原生构建或新页面真机验收。

接口依据：[GitLab Issues API](https://docs.gitlab.com/api/issues/)、[GitLab API 认证](https://docs.gitlab.com/api/rest/authentication/)。
