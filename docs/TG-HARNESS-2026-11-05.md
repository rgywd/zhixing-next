# TG 主动任务与跨入口控制修复

2026-11-05，陪伴插件 0.1.3，DSH 0.2.2-alpha.2、Messenger Gateway 0.4.23。

## 问题与改动

主动新闻使用插件的条件检查，并非原生定时提醒。旧 `companion_contact` 只在 TG 私聊挂载，只能暂停或调低频率；来源固定在源码里。App 收到修改 TG 来源的请求时找不到对应工具，TG 则将修改源码的文件权限与主动任务的控制能力混为一谈。

现在 App、原生 DSH 和绑定的本人 TG 私聊可读写同一份主动配置：来源、屏蔽话题、兴趣、时段和每日上限。字段部分更新后原子落盘；重启保留配置，设置变更会阻止生成中的旧草稿发送。历史读取仍只属于本人的 TG 私聊，群聊和子 Agent 不能修改这份私人设置。普通 `schedule_*` 原生工具保持原生会话归属与权限。

网关原来将繁忙时的补充消息交给 `followup`，但回复用户“加入当前轮”；现在改用原生 `steer`。原来的超时只结束网关等待，底层 Agent 仍可能运行；现在达到既有 `turnTimeoutMs` 后取消底层任务、等待原生结束，再返回明确的超时提示。没有更换模型、降低文件权限或加另一套轮数预算。

## 已验证

- 61 项 DSH 单元测试、623 项移动端测试、typecheck、lint 通过。
- 原生宿主集成覆盖现有 App 权限、审批、取消、恢复、文件和业务数据回归。
- 原生 App 模型调用共享工具保存配置，TG 模型读取同一结果，重启保留；TG 实际创建、修改、列出和删除原生定时任务。
- 慢速 App 模型请求期间 TG 和 HTTP 仍可响应；TG 超时后底层 turn/end 为 aborted、繁忙状态清除，下一条请求完成；插话落入原生 next-step。
- 真实 OpenAI Luna 收到自然语言“删除 TG 主动新闻里的 NASA”后调用共享工具并保存成功。Luna、Terra 经 Responses 调用原生 bash 并返回结果通过。TG 传输在隔离验收中使用本地回执，未发送额外生产测试消息。
