日期：2026-10-22。模型沿用之前验收过的百炼国际站 `qwen3.8-flash`，协议为 `chat_completions`。当次只读读取已启用的供应商配置，凭据留在服务器进程内，不进入公开证据或隔离运行的模型快照。

验收源码为 `5653ff0fc6aaca53d0541d25c8cc78ba2f70e208`，后端 Git tree 为 `396bbeecc390e1ad2c9feccac8e832ae085425ab`；随后的验收记录提交只修改文档，后端内容相同。实际使用模型工厂创建的真实客户端，运行真实 Deep Agents 图及真实记忆整理调用，再查询隔离 SQLite、事件、工具回执与来源。没有使用脚本模型代替供应商回答。

## 结果

最终一轮 10 次对话、25 项检查全部通过。使用虚构人物、偏好和 225 条占位记忆；只读生产模型目录，未向生产聊天、个人记忆、财务或健康记录写入验收资料。

| 场景 | 实际验证 |
| --- | --- |
| 产品身份与能力 | 主助手自称知行，不冒用 Muse/Meta/Spark；不声称可以打开浏览器、读取手机密码库或保证远程提醒 |
| 记住与偏好 | 真实整理保存人物关系、昵称、爱好和回答偏好；回复简短确认，不要求用户管理保存状态 |
| 较早事实 | 加入 225 条较新记录后，新对话仍召回较早的人物爱好 |
| 搜索、读取、出处 | 实际调用 `search_personal_memories`、`read_personal_memory` 和 `read_history_message`，内容与用户原始消息一致 |
| 专用助手 | 财务助手使用自己的身份，能读取共享个人记忆，没有记账副作用 |
| 纠正 | 更新旧爱好、保留未改信息，当前来源指向本次纠正消息，新对话使用新说法 |
| 遗忘 | 匹配人物关系、昵称和爱好退出记忆，其他偏好保留；本轮无报告、文件、委派或业务工具效果 |
| 遗忘后查询 | 不重新说出旧爱好，不从保留的旧聊天重建记忆，也不列出无关占位资料 |
| 数据边界 | 原聊天保留、财务无新增、隔离运行模型快照无密钥，SQLite 完整性和外键检查通过 |

实聊过程中发现并修复了三个问题：模型解释后台整理并要求用户回查；查无匹配后带入无关记忆；把单独遗忘误做成报告。最终版本从真实用户输入追加本轮确认约定，收紧无匹配的浏览回退，并让明确的单独遗忘由服务处理、不给模型额外操作工具。只读咨询和研究资料不构成新的用户授权；明确要求其他操作的混合输入保留相应能力。
