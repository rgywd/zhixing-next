# 设置入口验收 · 2026-09-29

底栏“工具箱”更名为“设置”，侧栏的设置入口移至此处。布局参考旧版知行 RikkaHub 的
[SettingPage](https://github.com/rgywd/zhixing/blob/main/app/src/main/java/me/rerere/rikkahub/ui/pages/setting/SettingPage.kt)
与 [SettingProviderPage](https://github.com/rgywd/zhixing/blob/main/app/src/main/java/me/rerere/rikkahub/ui/pages/setting/SettingProviderPage.kt)：
分组列表、供应商独立入口、默认模型独立入口，沿用 Next 的暖白底和语义色。

## 本次行为

- 模型与服务：供应商品牌列表、名称/模型检索与能力详情弹层；聊天/执行/记忆默认模型；搜索服务管理弹层。
- 助手：人格偏好、子智能体。人格表单保存后再次修改时清除旧的“已保存”状态。
- 数据与连接：资源库、服务连接和运行环境探索。连接设置不依赖人格接口加载成功。
- 设置中添加搜索服务后留在管理列表，不自动替换聊天的搜索选择；移除已选服务后清除相关引用。聊天内的“保存并使用”行为保持不变。

模型供应商地址、密钥及新增模型仍由服务端 TOML/环境变量管理；本次没有新增手机编辑模型供应商的接口。
目录中的“密钥已配置”只表示配置存在，不代表供应商调用已验证。搜索服务则通过现有认证接口在手机增删，密钥仅保存到服务端。

## 自动检查

- `npm run typecheck`：通过。
- `npm run lint`：通过。
- `npm run test:mobile`：23 项通过。新增管理入口添加不改选中项、聊天入口添加并选用、保存失败保留表单、删除批准/失败与引用清除的回归。
- `npm run bundle:android`、`npm run bundle:ios`：通过。

## Android 实际运行

使用独立 Android API 36 模拟器、Expo Go 57.0.9，在约 411dp 与 320dp 宽度检查。
后端运行仓库真实 FastAPI/SQLite，使用隔离测试数据与虚拟供应商配置，没有调用云模型或真实搜索服务。

| 场景 | 结果 |
| --- | --- |
| 未连接，从设置进入服务连接，填写并保存 | 连接成功，随后能够读取模型目录 |
| 320dp 设置首页及底部入口 | 可滚动到资源库和服务连接，底栏未遮挡滚动末尾的操作 |
| 按模型名 `qwen` 筛选供应商 | 只显示百炼；清空搜索恢复三家供应商 |
| 供应商详情 | 底部弹层显示品牌、模型标识与声明能力，系统返回关闭弹层 |
| 切换默认聊天模型 | 选择 DeepSeek 后重新 GET `/v1/models`，角色值已持久化 |
| 设置中新增搜索服务 | 创建成功，停留管理列表；GET 返回不包含密钥 |
| 移除搜索服务 | 确认后重新 GET 验证已删除 |
| 人格保存 | 重新 GET `/v1/assistant` 验证名字已保存 |
| 资源库、子智能体返回；聊天侧栏 | 回到设置首页；侧栏仅有搜索和记忆快捷入口 |
| 关闭服务后冷启动 App | 不依赖已加载人格，仍能编辑服务地址和访问令牌 |
