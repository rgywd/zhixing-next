# 移动端收尾验收 · 2026-10-04

本轮接续历史计划及模拟器审计。先合入已完成的 PR #13（模型思考适配与悬浮提示）和 #14（安卓通知、日历与单次定位），再基于 `f56fbfc` 完成以下改动。

## 完成范围

| 场景 | 当前行为 |
| --- | --- |
| 首页 | 上方常用、下方最近；可固定会话和项目，按加入顺序保留。最近混排实际会话、文件及打开过的项目，重开 App 后保留旧内容的访问记录；同一内容仍指向原实体 |
| 工作与项目 | 项目行可打开，全部项目及项目会话支持分页；新建项目进入详情，新建会话保留项目归属；从首页进入项目可返回首页 |
| 全部对话 | 直接复用历史和搜索侧栏，创建表单只在新建时出现；旧财务消息的搜索目标和返回来源保留 |
| 财务 | 紧凑页头与可收起速览，键盘打开优先保留消息；记录保留说明、时间，不重复显示空插画 |
| 资源 | 单层紧凑列表，服务端全库名称搜索、最新窗口及继续分页；明确加载/失败/重试/无匹配；预览和来源会话可打开 |
| 计划 | 本页选择结果会话、今天/明天/月历、时间、一次/每天/每周/自定固定间隔；保留持久草稿和原请求 ID 重试；区分暂停与一次已触发，运行后可查看所属会话 |
| 任务详情 | Markdown 结果、可下载交付文件，轨迹与用量默认收起；任务与事件独立读取，失败在详情内显示并可重试；审批、取消语义保留 |

首页偏好只在本机保存，按服务地址隔离；读取失败时禁止用空状态覆盖原偏好，支持重试。异步打开旧内容使用最新导航校验，迟到的请求不覆盖后一次导航。首 100 条之外已加载的计划使用按 ID 查询刷新状态。

## 图片空白的定位与修复

隔离 API 的 JPEG 响应可解码且与磁盘字节一致。独立 Android debug APK 的原生 Image 错误进一步确认图片请求返回 401。检查本项目锁定的 React Native 0.86.3 `Image.android.js`：数组 source 分支将 headers 转给 nativeProps，单对象分支没有该赋值。

共享资源图片改用单元素 source 数组保留 Bearer 头；没有关闭认证、把令牌放进 URL，或增加新的原生依赖。模拟器随后正常显示同一张图片，资源缩略图和全屏预览均通过。失败/超时重试反馈仍保留；测试覆盖认证头与重试 URL。

## 本地与模拟器验证

- 本轮自动测试：92 项移动测试、256 项后端测试通过；16 项 Docker 集成测试在本机未启用而明确跳过。TypeScript、ESLint、Ruff 通过。推送前在最终提交执行 Android/iOS JS bundle；CI 另含 Docker 执行与恢复门禁。
- Android API 36 ARM64，使用此前 #14 已构建安装的 `dev.zhixing.next` debug APK，从本轮 worktree 的 Metro 加载 JS；不是仅做 JS 打包，也不是 Expo Go。本轮未重建原生安装包，没有改变原生依赖或配置。
- 隔离的本机 API/SQLite、合成项目/消息/文件/财务记录。模型地址指向不可达本机端口，没有云模型调用或生产数据操作。
- 实际点击验证：首页固定项目并打开/返回；项目所属会话；全部对话历史；`finance-needle` 搜索命中旧财务消息；任务 Markdown 与交付文件；资源缩略图、全屏图片和 `csv` 搜索。
- 实际创建一次明日计划，独立读取 SQLite 回执确认只有一个计划、归属在本页选定的财务会话、`interval_seconds=null`，没有沿用此前全局选中会话。
- 检查浅色常规尺寸和深色 320 dp、字体 1.3。窄屏财务打开键盘后消息和输入工具可见，速览不占用消息空间；返回路径和草稿保留。
- 原始截图、计划回执与审计记录保存在验收机 `Documents/Codex/acceptance/zhixing-ui-audit-20261004/`，新截图以 `followthrough-` 开头，不提交到仓库。

这是界面和接口组合验收，不代表本轮重新验收了真实供应商、实体手机或 iOS 原生运行。生产没有部署本轮代码；新资源搜索、项目过滤和计划状态刷新接口需随服务端更新后使用。
