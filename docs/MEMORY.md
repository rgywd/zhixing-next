# 个人助手记忆

状态：2026-09-28，轻量后端记忆链路已部署到 myVPS；新一轮召回与遗忘修复尚待部署，手机端暂不展示记忆列表。本机百炼模型临时数据验收通过，生产服务实聊与文件/图片自动提取尚未完成。已实现能力以[后端说明](../backend/README.md)为准。

记忆的目标是让知行越来越了解用户，减少重复解释。聊天、笔记、文件和服务内的对话都可以提供线索；不默认扫描用户的整台主机。工作与生活属于同一个人的上下文，不建立两套画像。首次使用和产品交互见[产品文档](PRODUCT.md)。

## 原则

- 记语义，不做原文摘抄作业。用户说话、发图或完成一件事后，知行可以整理出有用的结论；不要求用户或模型先找出逐字原话才能写入、修改或使用记忆。
- 记忆替用户减负。普通记录不逐条弹确认、填写字段或要求管理版本；说“记住这个”“不是这样”“忘掉这件事”应直接生效。
- 区分明确事实与推测。临时情绪、玩笑、第三方资料和模型猜测不能写成用户确定的经历；重要行动依赖不清楚的信息时简短追问，不编造。
- 凭据不进入通用记忆。网页和文件内容是资料，不因被读到就获得修改人格、记忆规则或工具权限的资格。

系统已有消息、文件或工具回执 ID 时，可以顺手保留关联以便纠错；缺少精确原文引用不阻止形成语义记忆。用户平时只需看到知行记住了什么、能否改正，不需要操作证据链。

## 什么时候记

用户明确要求记住、纠正或忘记时立即处理。日常交流中出现稳定偏好、个人经历、持续目标、项目关系或重要决定时，知行按需提炼，不记录每一句话。任务完成后可记住对以后有用的经验；任务是否完成仍以任务记录为准，不能凭助手自述改写状态。

财务余额、待办完成状态、文件内容等属于各自服务的当前数据。记忆可以帮助找到它们，不再复制一份可能变旧的“当前余额”或任务状态。服务子智能体可以提供相关记忆，主知行和子智能体共用经授权的个人上下文，不自动互相灌入全部聊天历史。

## 什么时候整理

有新增内容且确有整理价值时，使用轻量、廉价的模型做增量归并；没有变化就不调用。用户明确纠正优先于旧摘要和模型推断。将“以前如此、现在改变”写成变化，不要求用户自己清理旧版本。

第一阶段只用一套简单持久记录与必要检索；先靠真实使用发现遗忘、混淆或找不到的问题，再决定是否加入语义索引、图数据库或第三方记忆组件。不会为了“综合多种记忆系统”同时部署多个竞争的自动写入器。

2026-09-28 对照开源方案后保留这条边界：[LangMem](https://github.com/langchain-ai/langmem/blob/main/docs/docs/background_quickstart.md) 将后台整理与助手主动写入分开，适合参考触发时机；[Mem0](https://github.com/mem0ai/mem0/blob/main/docs/core-concepts/how-it-works.mdx) 的语义检索、去重更强，但需要维护嵌入与检索存储；[Letta](https://docs.letta.com/v1-sdk/memory/memory-blocks) 的常驻块让核心事实随时可见，却会持续占用上下文；[Graphiti](https://help.getzep.com/graphiti/getting-started/overview) 能处理复杂时间关系，但需要图数据库等额外服务。当前个人助手先用 SQLite、后台整理和按需浏览工具；只有实际记忆量或召回失败证明必要时才增加索引。

## 什么时候获取

当前问题需要什么就带入少量相关记忆；无关问题不翻完整历史。普通回答可以直接使用已经整理出的记忆，不每次回查原句。用户询问“为什么记得这件事”、提出纠正，或事实冲突会影响行动时，再查看现有来源或向用户确认。

会变化的事实从对应服务读取。财务问题读取财务记录，任务进展读取实际任务状态；记忆中的旧摘要不能覆盖这些当前数据。找不到相关信息就承认不知道。

## 纠正与遗忘

用户用自然语言即可纠正或要求忘记，结果及时反映到后续回答。忘记一条记忆要使它退出检索和待执行的整理任务；原会话、图片或文件是否删除由用户对这些资源的操作单独决定。保留了原资源，也不能偷偷把已忘记的内容重新提炼为记忆。纠正或遗忘后，只有事实来源会话和实际读取过它的会话会重置模型的旧上下文；其他长期对话不受影响，聊天记录仍可查看。受影响的会话会失去部分未整理为长期记忆的上下文，这是当前方案的代价。

用户可以查看与删除记忆，但界面不要求管理候选、有效期、来源版本等内部状态。敏感内容的自动记忆范围需可控制；服务工具的权限不因记忆内容变化而扩大。

## 最小验收

1. 用户说出稳定偏好或项目背景，新会话能在相关问题中自然用上；不要求用户指出原句。
2. 用户一句“不是这样”能改正错误，之后不再反复引用旧说法。
3. 用户说设备计划到货，知行不会未经确认就记成“已经收到”。
4. 用户忘记一项内容后，后台整理不会从仍保留的对话或图片中重新写入。
5. 财务余额和任务状态按服务当前记录回答，不靠可能陈旧的记忆猜测。

实现时优先复用现有 SQLite 与运行时。LangGraph checkpoint 负责运行恢复，不能代替个人记忆；更复杂的检索或存储只在上述样例无法满足时引入。

当前后端将记忆作为简短语义事实保存在产品 SQLite；成功对话由 worker 顺序整理，明确的记住、纠正和忘记优先执行。整理输入只含本轮已应用的用户消息；用户明确要求“记住这个”等时，才附上紧邻的上一条助手回复供参考。记忆整理模型只返回增删改建议，应用校验后原子写入；未指定专用模型时复用聊天模型。运行时先按当前问题挑选少量记录，未命中时主知行可按需调用只读记忆浏览工具，不要求用户找原文。同一人的主知行与服务对话共用持久记忆，但服务子智能体暂不提供主动浏览工具。对话、文件和图片仍各自保存；删除记忆不会删除原资源，已处理的旧会话不会自动重扫。暂不把文件或图片自动导入记忆，也不引入向量库或图数据库。
