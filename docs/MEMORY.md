# 个人助手记忆

2026-10-22 第一轮源码：增加少量全局交流偏好常驻与明确人物称谓／昵称召回。继续使用同一份 SQLite 事实和整理器，数据库保持 v14；没有第二套画像、人物档案或后台定时学习。实现边界与真实模型结果见[第一轮验收记录](ACCEPTANCE-CORE-MEMORY-2026-10-22.md)，部署状态以本轮 PR 的实际回执为准。

## 核心偏好和人物称谓

- 称呼、回答语言、长短、先结论等全局交流偏好从整库当前事实派生，每轮最多四条、总计 800 字，整条带入且不截断。较新的同类偏好优先；饮食、人物隐私、业务数据、条件性偏好或工具授权不作为常驻画像。当前用户请求及服务助手职责优先，偏好不能授予工具权限。
- 每次模型调用提醒实际带入的表达偏好，并在主／直接助手的当前真实用户输入副本附近补充有界提示，避免长上下文淹没偏好；数据库、checkpoint 原话、图片及来源不被改写。用户本次明确要求详细解释时可以覆盖长期简短偏好，单次要求不改写长期记忆。句数限制保留原适用范围。
- 人物召回只使用明确的姓名、关系和昵称声明，例如“阿岚是用户的伴侣”。新会话中的“我对象”可以关联这些事实，再读取有关阿岚的记录；不凭一个“她／他”或共同爱好认人。同称谓或昵称指向多人时保持歧义，只有影响回答或操作时简短询问，不按最近记录选人。
- 旧关系、否定关系与有歧义的映射不作为当前身份。中性伴侣称谓与明确关系可建立联系，不能从中性称谓推断婚姻或性别。名字、昵称和称谓识别是有限的中文规则，并非通用实体识别或语义向量检索；未识别的表达仍可由相关关键词继续查找。
- 所有视图均直接引用当前事实及其版本，不生成独立持久摘要。实际带入的偏好、相关事实，以及作出称谓关联／歧义／旧关系判断所依赖的事实均登记暴露版本。纠正或忘记后沿用现有会话失效和旧整理隔离，避免派生关联继续沿用旧说法。无法撤回已经开始生成的当轮回答。
- 新增人物关系或昵称若改变原称谓的唯一性，也会使实际读取过旧映射的会话上下文失效；重复已有关系或增加普通爱好不触发这种重置。原事实和聊天仍保留。
- 单独询问一个未指明人物的喜好时，模型菜单与工具执行层都会先收紧，本轮只用当前真实输入询问指谁，不借旧候选资料或泛搜其他聊天认人。混合请求可继续独立业务操作；含糊的人物部分等待澄清。同一聊天中最近真实用户输入明确指向一个人时，可以用该姓名定向查找；助手猜测、系统注入和其他聊天不建立代词身份，多人不能强挑一位。Steer 明确身份后重新判断，不要求用户管理状态。
- 主知行、直接及命名委派助手共享这些有上限的上下文；限定来源的研究助手仍不接收个人画像或扩大检索范围。无关问题不带入人物档案或完整记忆库。

整理器仍是唯一的模型写入入口。全局交流偏好与人物信息分开保存，人物事实保留明确姓名，纠正时保留仍有效的关系或其他偏好。整理时额外提供少量核心偏好和本次关系关联的依据，使较早的偏好和称谓也能被正确修改；不重扫旧聊天。明确记忆请求仍沿用回复后优先整理及失败通知的时序，本轮不改变保存确认协议。

## 按需搜索与来源

2026-10-22 补充：明确的单独遗忘请求不向模型提供工具，交由记忆服务处理，避免把待忘内容另存为报告或发起业务写入；同时明确请求报告或其他操作的混合输入保留原能力。

日常的记住、纠正和忘记只简短确认意图，不介绍内部整理时序、工具权限或要求用户核实结果。运行时从本轮已应用的真实用户输入补充确认约定；只读咨询、历史和研究资料不能因此变成记忆操作授权。实际整理失败继续由服务发出未生效通知。

- 自动召回从全库按中文双字／英文词匹配选出少量相关事实，不再局限最近 200 条；没有匹配时仅明确的个人记忆总览问题带少量近期记忆，具体问题不会因为带“我”或“记忆”字样而混入无关记录。
- `search_personal_memories(query, offset)` 只返回匹配项，每页最多 25 条，按实际 `next_offset` 续读；`browse_personal_memories` 继续支持没有关键词的顺序浏览。本轮实际关键词搜索无匹配后，模型菜单暂停顺序浏览，但保留换相关关键词再查；新一轮总览可以恢复浏览。无匹配只表示没有找到相关保存信息，不能推出全库不存在其他事实，也不展示无关记录填补答案。主知行、直接与委派命名助手共用这些只读工具；受指定文件范围限制的研究助手不会因此扩大来源。
- `read_personal_memory(memory_id)` 返回当前内容及可用的来源消息引用。需要解释“怎么知道”时再用 `read_history_message` 查原话，普通回答不要求回查或让用户找引文。找不到来源就说明未知，不编造出处或完整修订历史。
- 整理模型先拿到近期事实及全库检索命中的旧事实，便于修正更早的偏好或人物关系。每次整理接收近期 100 条及相关 100 条，并补充有上限的核心偏好和关系关联依据，去重后提交最多八项操作。
- 自然语言新增／纠正可绑定本次运行中已应用的具体用户消息，包括 Steer；程序拒绝其他对话、助手消息或未应用消息作来源。省略来源时保留旧调用的兼容默认值，即本次原始用户消息。纠正会更新来源；手动编辑没有对应聊天原句，清除旧来源而不继续归因给旧话。纠正只重置原来源及实际读过该条的会话。
- 新工具读取也登记实际暴露版本；之后纠正或遗忘会使读过它的上下文失效。被遗忘的记录不能通过新搜索或单条读取恢复；原始聊天仍按已有规则保留。

检索仍是词法匹配，不是语义向量搜索；例如没有共同关键词的昵称或同义表达可能漏召回。没有新增独立人物档案、自动扫描文件／图片、全天后台自我改进或新的提醒机制；来源也不是历史每一版的审计链。数据库保持 v14。定向与既有回归使用测试模型和真实 SQLite，云端模型效果及生产部署另行验收。

## 原则

- 记语义，不做原文摘抄作业。用户说话、发图或完成一件事后，知行可以整理出有用的结论；不要求用户或模型先找出逐字原话才能写入、修改或使用记忆。
- 记忆替用户减负。普通记录不逐条弹确认、填写字段或要求管理版本；说“记住这个”“不是这样”“忘掉这件事”应直接生效。
- 区分明确事实与推测。临时情绪、玩笑、第三方资料和模型猜测不能写成用户确定的经历；重要行动依赖不清楚的信息时简短追问，不编造。
- 凭据不进入通用记忆。网页和文件内容是资料，不因被读到就获得修改人格、记忆规则或工具权限的资格。

系统已有消息、文件或工具回执 ID 时，可以顺手保留关联以便纠错；缺少精确原文引用不阻止形成语义记忆。用户平时只需看到知行记住了什么、能否改正，不需要操作证据链。

## 什么时候记

用户明确要求记住、纠正或忘记时立即处理。日常交流中出现稳定偏好、个人经历、持续目标、项目关系或重要决定时，知行按需提炼，不记录每一句话。任务完成后可记住对以后有用的经验；任务是否完成仍以任务记录为准，不能凭助手自述改写状态。

财务余额、待办完成状态、文件内容等属于各自服务的当前数据。记忆可以帮助找到它们，不再复制一份可能变旧的“当前余额”或任务状态。服务子智能体可以提供相关记忆，主知行和子智能体共用经授权的个人上下文，不自动互相灌入全部聊天历史。

## 什么时候整理

有新增内容且确有整理价值时，使用轻量、廉价的模型做增量归并；没有变化就不调用。用户明确纠正优先于旧摘要和模型推断。将“以前如此、现在改变”写成变化，不要求用户自己清理旧版本。

第一阶段只用一套简单持久记录与必要检索；先靠真实使用发现遗忘、混淆或找不到的问题，再决定是否加入语义索引、图数据库或第三方记忆组件。不会为了“综合多种记忆系统”同时部署多个竞争的自动写入器。

## 什么时候获取

当前问题需要什么就带入少量相关记忆；无关问题不翻完整历史。普通回答可以直接使用已经整理出的记忆，不每次回查原句。用户询问“为什么记得这件事”、提出纠正，或事实冲突会影响行动时，再查看现有来源或向用户确认。

会变化的事实从对应服务读取。财务问题读取财务记录，任务进展读取实际任务状态；记忆中的旧摘要不能覆盖这些当前数据。找不到相关信息就承认不知道。

## 纠正与遗忘

用户用自然语言即可纠正或要求忘记，结果及时反映到后续回答。忘记一条记忆要使它退出检索和待执行的整理任务；原会话、图片或文件是否删除由用户对这些资源的操作单独决定。保留了原资源，也不能偷偷把已忘记的内容重新提炼为记忆。纠正或遗忘后，只有事实来源会话和实际读取过它的会话会重置模型的旧上下文；其他长期对话不受影响，聊天记录仍可查看。受影响的会话会失去部分未整理为长期记忆的上下文，这是当前方案的代价。

用户可以查看与删除记忆，但界面不要求管理候选、有效期、来源版本等内部状态。敏感内容的自动记忆范围需可控制；服务工具的权限不因记忆内容变化而扩大。

当前主线的纠正与遗忘在同一事务中隔离旧的未完成整理：直接操作会跳过当时已存在的待整理、运行中和失败运行；自然语言纠正或遗忘会跳过该请求之前的这些运行。因此失败整理后来重试，或模型已经读完旧内容后才返回，都不会重新写回旧说法。之后的新输入仍能形成记忆。当前没有语义级别的逐事实隔离，这些旧运行里其他尚未整理的事实也不会补录；原始聊天和任务执行不受影响。读取记忆与纠正同时发生时，会核对实际读取版本，让受影响会话在下一轮清除旧模型上下文；无法撤回已经开始生成的当轮回答。

## 最小验收

1. 用户说出稳定偏好或项目背景，新会话能在相关问题中自然用上；不要求用户指出原句。
2. 用户一句“不是这样”能改正错误，之后不再反复引用旧说法。
3. 用户说设备计划到货，知行不会未经确认就记成“已经收到”。
4. 用户忘记一项内容后，后台整理不会从仍保留的对话或图片中重新写入。
5. 财务余额和任务状态按服务当前记录回答，不靠可能陈旧的记忆猜测。

实现时优先复用现有 SQLite 与运行时。LangGraph checkpoint 负责运行恢复，不能代替个人记忆；更复杂的检索或存储只在上述样例无法满足时引入。

当前后端将记忆作为简短语义事实保存在产品 SQLite；成功对话由 worker 顺序整理，明确的记住、纠正和忘记优先执行。整理输入只含本轮已应用的用户消息；用户明确要求“记住这个”等时，才附上紧邻的上一条助手回复供参考。记忆整理模型只返回增删改建议，应用校验后原子写入；未指定专用模型时复用聊天模型。运行时先按当前问题挑选少量记录；主知行、直接服务助手和委派助手都可按需调用只读记忆浏览工具，不要求用户找原文。同一人的这些对话共用持久记忆，跨对话的内部助手咨询不作为新的个人事实来源。对话、文件和图片仍各自保存；删除记忆不会删除原资源，已处理的旧会话不会自动重扫。暂不把文件或图片自动导入记忆，也不引入向量库或图数据库。
