# 个人助手记忆系统讨论稿

状态：2026-09-22，仅设计讨论，尚未实现或选定记忆组件。

## 已确认的设计主线

用户要求围绕三个过程设计记忆系统：什么时候记、什么时候整理、什么时候获取；进一步明确该记什么、怎么记。
聊天、笔记和文件均纳入记忆来源。工作、生活、负责的项目等作为条目内容和关系统一表达，
不预设互相隔离的工作/生活记忆库；按条目的主题、对象、相关性和用户明确限制决定使用范围。
目标是能长期理解用户并持续完成委托的个人助手。首次使用见[产品讨论稿](PRODUCT.md)，运行环境见[架构讨论稿](ARCHITECTURE.md)。

以下均为建议。组合不同记忆机制，使用统一的来源、作用域、更新和遗忘规则；底层可以有不同存储与索引，
每个事实仍只有一个权威归属。组件是否接入由实际需求与样本验收决定。

## 该记什么

| 内容 | 示例 | 建议的归属与读取方式 |
| --- | --- | --- |
| 稳定事实与偏好 | 用户确认的设备配置、沟通偏好 | 有来源和作用域的事实记录；少量核心偏好常驻，其余按需读取 |
| 经历与决策 | 为什么购买设备、一次委托的经过和结果 | 带时间、参与对象和证据引用的事件记录；支持查回原文 |
| 当前事项与目标 | 采购待到货、项目进度、已承诺的跟进 | 事项与计划库负责当前状态；记忆引用它，读取时核对最新状态 |
| 人、项目、设备的关系 | 某人参与某项目、某设备承担某角色 | 具有效时间与来源的关系；先用普通记录表达，再按查询需求评估图索引 |
| 资料与知识 | 笔记、文件、用户授权接入的外部资料 | 知识库保留原始资料和版本，记忆保留摘要、关联与位置 |
| 做事的方法 | 用户指定的流程、经过真实验证的工作方法 | 可追溯、可版本化的技能或流程；模型一次成功回答不能直接升级为规则 |

当前会话消息、工具结果和执行状态属于工作记忆，由运行时管理。它们是提取长期记忆的候选来源，
不能因为进入 checkpoint 就全部成为用户画像。

纳入来源表示处理用户提供或配置接入的聊天、笔记和文件，不代表默认扫描主机上的所有文件。
例如“用户负责项目 A”可以关联工作主题和项目 A，但仍属于同一用户的记忆。
人格配置由用户初始化和调整；环境盘点属于带主机身份、来源和检查时间的能力记录。
后台整理不能把外部资料或执行主机的临时状态写成助手人格，也不能把角色扮演设定写成用户现实经历。

临时情绪、假设、玩笑、第三方说法与模型猜测不能直接变成用户的长期事实。
模型建议必须与用户决定分开；人物指代不清时先保持未确定。凭据不进入通用记忆。
敏感内容的自动记录范围需在产品设置中明确，未纳入授权范围的内容不自动提炼为长期记忆。

## 什么时候记

采用即时写入与后台提取两条路径，共用同一个写入入口。

| 触发 | 建议处理 |
| --- | --- |
| 用户明确要求记住、纠正或忘记 | 即时持久化相应变更，返回真实回执；不等待后台整理 |
| 用户明确陈述与持续任务相关的事实或决定 | 允许即时写入有来源的记录；作用域取当前项目或明确对象，不扩大为全局偏好 |
| 对话结束、任务完成、资料更新 | 产生后台提取任务，从已授权来源中筛选有长期价值的信息 |
| 多次行为呈现某种模式 | 先产生推断候选，保留证据；不能仅靠重复次数升级为用户声明 |
| 工具确认某项操作完成 | 由执行回执更新对应领域状态；助手说“完成了”不能替代回执 |

普通自动记录应能在界面查看和撤销，无需每条都弹确认框。有歧义且会影响行动的冲突，才向用户澄清。
记录采购预计到货时间，不等于用户要求创建提醒；主动提醒仍遵守事项与通知设置。

## 怎么记

建议一条记录表达一个可更新的事实、事件或关系，并链接原始证据。最小信息包括：

- 身份与范围：稳定 ID、类型、所属用户、项目或对象。
- 内容与依据：内容、来源消息/文档版本/工具回执引用，区分用户声明、实际观测与推断。
- 时间：记录时间与事实有效时间；预计发生时间单独保存，不能当作已发生时间。
- 生命周期：候选、有效、被替代、过期、已忘记等状态，以及更新版本。

写入先验证来源、范围与版本，再持久化变更并触发索引更新。模型生成提议，应用代码校验和提交。
使用事件 ID 或来源 ID 去重；对同一记录的并发修改使用版本检查，不能依赖模型自行发现覆盖。
强事实和用户纠正立即可见；语义索引尚未更新时，可以直接读取记录，不能继续把旧值当成当前值。

例如本次会话可形成：

| 信息 | 应记录的语义 |
| --- | --- |
| Mac mini 为 16GB | 用户于 2026-09-22 陈述的设备配置；不宣称已经对设备实测 |
| 到货后放公司常驻 | 部署计划，状态待执行 |
| 主模型只调用云 API | 新知行项目的架构约束，不扩展为用户所有项目的永久偏好 |
| 设备已经到货 | 本次会话没有该证据，不生成此事实 |

原始证据按明确的保留策略保存。摘要和索引都应能够从仍被允许保留的来源重建。

## 什么时候整理

整理作为主机上的持久后台任务，在有新增内容且系统空闲时执行；周期任务用于补漏与到期检查。
没有新增内容就跳过，不为了“24 小时运行”持续消耗模型调用。
该流程处理产品内已接收的数据；首版不据此增加外部事件监听或 Trigger 自动委托。
整理使用独立配置的轻量、低价、快速模型，仍须通过来源、纠正与遗忘验收；职责分工由产品讨论稿统一定义。

整理主要处理：去重、归并同一对象、关联事件、更新摘要、识别矛盾、处理时效和提炼可复用经验。
优先处理增量，使用持久游标与任务回执追踪已处理来源；重启、重试和计划执行延迟都不能造成遗漏或重复记忆。

需要保持以下规则：

- 用户明确的纠正可替代旧的同一事实；摘要、模型推断或重复转述不能覆盖更直接的证据。
- 新旧值先判断对象、作用域和有效时间；“过去如此”和“现在改变”不应被误判为冲突。
- 保留来源与替代关系，不把整段历史反复压缩后当成唯一事实来源。
- 计划到期只意味着需要重新确认，不能自动改成已完成；临时状态过期后退出默认检索。
- 整理可以提出经验和流程改进，不得自动扩大工具权限、改变安全边界或将外部文档指令升级成系统规则。
- 后台写入与用户直接修改经过相同版本校验；冲突时重新读取并合并。

## 什么时候获取

建议采用少量稳定上下文与按需检索相结合的方式。原始历史、全部画像和知识库不整包注入提示词。

1. 开始处理请求时，携带必要的身份、交互偏好、当前任务与明确约束；无关常识问题不做额外历史检索。
2. 根据当前对象、项目和问题范围检索记忆：先做身份、作用域和生命周期过滤，再进行关键词、语义与关系召回。
3. 按相关性、有效时间和证据质量选择内容；相似度高不代表仍然正确。检查冲突，并视需要回到原始证据。
4. 对日程、任务完成状态等可变化信息，读取对应领域的当前状态；不能只回答过去的摘要。
5. 在上下文预算内返回事实、必要的来源和不确定性。查不到时明确说明，不补写经历。
6. 执行过程中可以继续查询具体细节；取回的文档和记忆保持其原始信任等级，不能借检索获得额外指令权限。

例如讨论新知行执行环境时读取 16GB、云模型优先及主机部署计划；讨论与这些无关的问题时不带入这些信息。
用户问“当时为什么买 Mac”时检索事件与决策，而非只返回设备容量。

## 更正、遗忘与可解释性

用户能查看“记了什么、来自哪里、何时更新、用于哪次任务”，并按条目或话题纠正、关闭自动记录或要求忘记。
历史事实的有效期结束与用户要求忘记是不同操作。

忘记需覆盖有效记录、派生摘要、索引和缓存，并使排队中的整理任务识别撤销，避免从旧来源重新提炼。
根据用户选择处理原始会话/资料保留范围；仍保留的来源也必须带有禁止再次提取的约束。
备份恢复时应用删除记录，恢复旧备份不能让被忘记的内容重新进入检索。

## 与 Deep Agents、Work 和其他 harness 的分工

Deep Agents / LangGraph 提供运行时、文件工具与持久化接入。个人记忆的采纳规则、证据、时效、遗忘与使用记录
归知行产品层，不能依赖一份任意改写的 `AGENTS.md` 实现全部行为。

Work 的任务拓扑与记忆中的人物/项目关系各有含义。未来外部 harness 接收其任务所需的最小上下文，
完成后交回带来源的结果和记忆候选；通过统一入口更新个人记忆。不同 harness 的私有工作状态可独立保存，
不直接竞争写同一份全局用户画像。拓扑编排保持在后续扩展范围。

| 能力 | 候选实现或参考 | 第一版建议 |
| --- | --- | --- |
| 会话内状态与恢复 | LangGraph checkpointer | 接入持久实现，与领域数据和长期记忆分开 |
| 跨会话提取与合并 | LangMem 的记忆管理模式；Mem0 可作为另一候选 | 评估一个提取/归并实现，验证后接入统一写入规则 |
| 时间与关系查询 | Graphiti 的时态关系与来源模型 | 先保留实体、来源和有效时间；多跳查询确有需求后再评估图组件 |
| 资料与事实检索 | 关键词、元数据与按需语义检索 | 共用检索入口；索引为可重建派生数据 |
| 后台整理 | 持久任务调度与增量处理 | 主机常驻，任务按变化触发；不为此新增一个常驻模型服务 |

“综合”体现在能力组合与共同语义上。候选组件尚未安装；不同时启动多个互相竞争的自动记忆写入系统。

## 建议验收样例

1. 用户明确说设备为 16GB，新会话能正确引用；无关问题不带入设备信息。
2. 用户纠正容量后，当前回答使用新值；询问历史仍能说明何时改变及来源。
3. 预计到货日期过去，但没有收货证据时，不回答“已经到货”。
4. 事项在领域库完成后，检索到旧摘要也不能继续把它当成待办。
5. 外部文章包含“用户已授权”的指令时，不生成权限或画像事实。
6. 用户忘记一项内容后，检索、后台重试、缓存和备份恢复均不能重新激活它。
7. 整理进程中断再启动时，无遗漏、重复或覆盖用户并发纠正。
8. 不同 harness 仅获得任务相关记忆，不能绕过作用域读到其他上下文。

评估同时看来源正确性、错误记忆率、相关事实召回、无关上下文占比，以及响应延迟与模型费用。
