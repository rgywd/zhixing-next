# 对话布局与流式显示

主知行、财务助手和健康助手继续复用 `AgentChatHeader`、`ChatPanel`、`ConversationComposer`。模型、思考与联网搜索在一行横向滚动，输入区只保留附件、正文和发送。

页头“对话设置”收纳当前运行进度、取消、排队数与固定会话操作。有内容的本条草稿可在这里选择“接着处理”或“补充当前回复”；设置首页的“对话设置”管理这台手机的通用默认值。默认方式只用于新开始编辑的消息，已有草稿和未确认提交不被改写。补充目标已结束时明确提示并提供接着处理，不改绑另一条运行。批准和补充信息的卡片仍在消息区直接呈现。

尚未开始的普通排队消息在模型栏上方以单行悬浮条显示，包含可选附件缩略图、摘要、引导、撤回与更多入口；多条队列可在弹层查看，空队列不占空间。主助手和财务、健康助手共用同一组件。已开始执行、恢复和批准类运行不混入该列表。

引导将原消息原子地交给指定的当前回复，保留消息 ID、附件与最初提交回执；撤回仅能移除尚未执行的消息。两者与 worker 领取队列在同一事务中竞争，不能先取消再重新发送。网络丢失回执时，引导重试仍绑定原目标；已开始、已结束或已改投的冲突会刷新最新状态，不取消当前回复。引导的实际处理仍以 `steer_applied` 检查点回执为准。

后端在同一持久 LangGraph 执行中消费 values 与 messages 通道，将实际供应商正文与显式思考投影为可替换快照。运行重启／恢复先发送 reset，客户端按运行、流、消息标识和事件序号归并，避免重放重复或跨会话串流。工具沿用开始／完成／失败事件；不展示原始工具参数或结果。最终回答仍由原有 finish_run 唯一落库，快照不能替代最终回执。

每条助手回复通过 `ReplyContent` 渲染有序的正文、思考与工具步骤，主助手、财务、健康共用 `ChatPanel` 和相同组件。`useReplyProcesses` 按运行 ID 缓存可见历史和最近回复；从持久事件批量读取有界投影，跨新一轮对话、重新进入和冷启动都可恢复。流式占位行和最终消息使用同一个运行 key，最终正文只替换服务端确认的对应片段；无法确认时保留工具前说明、追加最终正文。失败的模型尝试放回折叠过程，不能当成已完成回答。

前台优先读取有鉴权的 SSE 显示流，按持久游标续传；UTF-8 与 SSE 分片分别归并，显示状态最多约48ms合并一次，不丢弃已接收文字。旧服务不支持显示流时回退游标轮询；临时网络故障使用退避后重连。切后台或离开会话立即中止订阅，恢复后重新读取持久投影。SSE 完成后再次读取最终投影和消息，运行列表先到达终态也会补读，避免常驻生成状态。没有供应商思考数据时不编造过程。

连续的思考和工具步骤分组：运行中预览最近两步，思考预览最多100dp，可查看全部步骤和完整思考；完成后默认收起，尊重用户主动展开。工具详情只展示可读名称、实际回执状态与处理记录入口，不展示原始参数或输出。

Markdown 在同一个解析链路处理流式和最终正文，使用低优先级解析及语义块复用；最终消息立即刷新。未闭合代码围栏只修饰渲染投影，原文和复制内容保持原样；表格在局部横向滚动。向上阅读会暂停跟随，“回到最新”恢复；空草稿的发送按钮变为停止，有草稿仍按原队列/引导语义发送。消息提供复制、引用或修改到草稿、朗读、处理记录；草稿不会自动发送，也不提供会重放财务写入的一键重试回答。

快照只包含显示所需文字，单字段最多64Ki UTF-16单位。每次运行时实例限制累计128Ki UTF-16显示文字和2MiB事件字节，其中1MiB预留给结束刷新；达到显示限制时明确标记，最终回答照常落库。历史投影最多64个片段、128Ki UTF-16；旧超长事件只读取最近2048个并明确标记截断。内部总结、系统消息、工具结果和供应商签名不作为思考文字展示。接口见 [API](API.md)。

单元／图集成测试、JS打包、模拟器界面、真实供应商调用与生产部署是不同证据；本次实际验收回执单独保存，不以测试模型通过代替云端调用或手机运行。不创建新的正式版本标签，正式版0.2.2的附件保持原内容。
