# DSH 对话配置

设置 → 对话设置提供两项云端配置：新会话默认权限、繁忙时的发送行为。模型与插件配置仍使用原有 DSH 入口，本次不增加模型供应商编辑器。

- 默认权限直接读取 DSH 的 `permission.defaultPreset` 和原生 `defaultOptions`，修改只影响之后创建的主知行、财务、健康会话；已有会话及欢迎页显式选择的权限继续保留。
- 繁忙发送直接读写 `ui-conversation.busyEnter`，提供“排队发送 / 插话发送”。发送时未单独指定方式的消息由宿主使用最新配置，避免手机缓存陈旧导致使用旧默认值。原生 DSH 负责空闲时直接发送、运行时排队或插话。
- 单条消息在输入框「+ → 发送方式」中选择“跟随云端默认 / 排队发送 / 插话发送”。显式选择随草稿恢复，未确认请求保留原编号和发送选择，成功发送后下一条回到云端默认。新配置不重新排列已提交队列。

## 数据与同步

`GET /v1/settings/chat` 只投影这两个配置项：`writable`、`permission`、`busy`。每项包含 `value`、`options`、不透明 `revision`；宿主未提供某项时返回 `null`。不返回配置文件路径、整个配置文档、模型密钥或其他命名空间。

`PUT /v1/settings/chat` 接收 `{ key: "permission" | "busy", value, revision }`，通过 DSH 原生 `settings.mutate` 只改一个字段。保存等待持久化完成并核对生效值，再返回完整的两项投影。无效值拒绝，旧版本返回 409；宿主重启也会使旧写入版本失效。失败保留已确认的配置，用户刷新后重新选择，不自动覆盖其他端的修改。

App 复用 SQLite 读缓存，按服务地址与令牌派生的身份隔离。缓存包含上次确认的配置和同步时间，不含令牌明文。打开先恢复缓存，24 小时内复用；启动 App、打开对话设置或回到前台时检查过期状态，过期才后台请求，不定时轮询。手动刷新可立即读取云端；手机保存成功后立即更新缓存并重新计算有效期。相同读取合并，旧响应不能覆盖保存回执。

离线仍显示上次同步值及错误，修改失败可重试，不排队离线写入。缓存写入失败不会把成功的云端保存回滚为失败；界面提示本机缓存未保存。断开连接后没有本机配置替代云端配置。
