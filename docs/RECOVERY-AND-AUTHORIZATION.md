# 中断恢复、授权与操作回执

2026-09-29，在通用执行能力升级后接入。保留单 worker、Deep Agents / LangGraph 原生 checkpoint 和 SQLite；以下描述当前实现，不代表生产部署或云模型已经验收。

## 用户使用链路

正常任务继续自主执行：读资料、在工作目录生成文件、运行离线脚本不逐步弹窗。默认只有以下情况需要决定：

| 情况 | 手机展示 | 批准范围 |
| --- | --- | --- |
| 替换额外授权目录的已有文件 | 目标路径、文本差异、大小，可下载原件和完整新文件 | 当前任务的这次写入，以及批准时的文件版本 |
| 配置了 bridge 网络的执行任务首次使用脚本或浏览器等工具 | 任务目标及 Docker 可达网络范围，明确包含内网和外部写入可能性 | 本任务内联网执行；仍受工具、目录和资源限制 |
| 重启后某一步已开始，但无法确认副作用结果 | 工具与参数，选择“保留现状，继续核对”或“允许重新执行（可能重复）” | 当前这次不确定操作；重试再次中断需要重新决定 |

批准卡显示在聊天、财务页和任务详情。等待期间进度落盘，不占用聊天/任务执行槽；同会话后续 Queue 保留原顺序，其他会话可以继续。批准或拒绝由认证 API 落库后，worker 继续原运行。模型文字、网页内容和 LangGraph resume payload 都不能代替该决定。

拒绝替换后，本任务不能通过换一个工具调用 ID 反复请求覆盖同一目标。文件在等待期间发生变化时，旧批准失效，返回真实错误，让模型重新读取。取消等待中的任务会撤销待批准请求、保留后续队列并暂停该会话。

## 恢复到什么程度

运行时开启恢复标记后，正常服务停止或进程重启会把在途运行放回队列，继续同一 run_id 和原生 checkpoint；不会把原始要求重复当作新任务发送。先清理旧容器并记录停止回执，再领取任务。尚未应用的 Steer 保留并按原有 checkpoint 规则确认。

operations 以运行 ID 和工具调用 ID 标识步骤，先保存操作计划，再记录开始和结果。它与 LangGraph checkpoint 相互补充：节点重放时先查看回执，不把节点重新进入当作副作用尚未发生。

- 物理 write_text_file / copy_file 保存待写入内容和原件快照、前后 SHA-256。恢复时目标已与计划内容一致则直接核对成功；目标还是原版才允许完成写入；出现其他版本则停止覆盖。成功回执重放前也检查文件是否仍存在且内容一致。
- 文件发布采用原子替换，并在发布前再次比对原件；本服务同一目标使用文件锁。取消在途文件写入时等待实际完成并保存回执，不把“已请求取消”说成“从未写入”。这仍以可信单用户宿主为前提，不声称隔离恶意本机进程的竞争修改。
- 已提交的定时计划、后台任务可以按服务稳定 ID 查询真实记录，补齐回执并继续。
- Shell、浏览器、财务写入等其他步骤若只有“已开始”记录，不自动重放；选择保留现状后，模型收到明确的未确认结果，必须先核对。选择重试可能产生重复效果。不能对任意命令或外部系统承诺 exactly-once。
- 最终模型回复已进入 checkpoint、但助手消息尚未提交时，恢复会交付已有回复，不重新调用模型。

连续恢复最多自动入队三次，再次中断标为 interrupted 并暂停队列。任务详情可以“核对已有步骤并继续原任务”。如果同会话已执行后续运行，则拒绝回到旧 checkpoint，需发送新要求核对结果。“继续队列”仍只推进未开始的输入，不重做失败或取消的任务。

恢复期间模型、图片能力、目录/执行权限、助手配置、记忆重置版本或 SDK 版本变化会停止旧运行，要求按新条件核对已有结果。容器、进程和浏览器会话重新创建，只有工作文件持久保存；不恢复在途进程或网页登录状态。

## 配置与执行边界

```toml
[[grants]]
path = "/absolute/path/to/documents"
writable = true
overwrite = "ask" # 默认；明确允许持续替换时可配置为 allow

[execution]
enabled = true
image = "zhixing-sandbox:1"
network = "none" # bridge 允许 Docker 可达网络，包含内网
network_authorization = "ask" # bridge 时每任务一次；明确持久授权可设置 allow
memory_mb = 2048
cpus = 2
timeout_seconds = 120
```

现有配置未声明新字段时使用 ask。已有可写目录仍允许新建文件；只读目录、未授权路径和受保护文件继续拒绝访问，批准接口不能扩大目录访问范围。overwrite=allow 也不把只读目录变为可写。

Shell 仍只运行在隔离容器中；CPU、内存、进程数、命令时限、容器生命周期和输出上限保持不变，见[执行边界](HARNESS-UPGRADE.md#执行边界)。批准不关闭这些限制，也不是对任意外部目标的无限授权。联网任务内不逐命令判断脚本是否“只读”；外部操作仍必须遵守用户具体任务范围。fetch_public_page 和搜索原有的公网读取限制不变。

## 数据与迁移

数据库自动迁移到 v9，增加操作和批准表，以及运行的 phase、recovery_enabled、recovery_count。升级前已在途的旧运行没有恢复标记，继续采用 interrupted 和人工核对行为，不能猜测旧工具是否已经完成。

文件快照在 `data_dir/operation-files/<operation_id>/{before,after}`，锁文件在 `operation-locks`。文本写入最大 256 KiB，复制及可备份原件最大 20 MiB；超过限制明确失败。批准下载会验证 SHA-256。当前保留快照支持核查，没有一键回滚、自动保留期或总量清理；需要按实际磁盘增长管理容量。

升级和备份前停止接收任务与 worker，确认文件工具和容器结束。一致性保存 app.sqlite、checkpoints.sqlite、资源、工作文件、操作快照及配置，不能只恢复其中一个数据库。旧版本不支持 v9；回滚使用完整升级前备份，保留升级后产生的文件和回执另行核对。

## 验证与未验收范围

回归使用真实 SQLite、真实 Deep Agents 图和真实 Docker，模型决策由测试模型驱动。覆盖文件写入前后、回执保存后、最终 checkpoint 后的中断；批准与拒绝、多请求等待、子助手批准续接、文件版本冲突、Steer、取消、队列顺序、自动恢复上限、旧数据库迁移，以及命令已产生效果但回执缺失和获准重试再次中断。

验证命令：后端 `ZHIXING_TEST_DOCKER=1 uv run pytest -q`、`uv run ruff check .`；客户端 `npm run typecheck`、`npm run lint`、`npm run test:mobile`、`npm run bundle:android`、`npm run bundle:ios`。普通 pytest 跳过 Docker 测试时，不可当作实际 Shell 验收。

本轮未连接真实云模型，未部署 myVPS/Mac mini 常驻服务，未执行 APK/iOS 原生构建及真机验收。批准卡复用共享 UI 并使用可换行按钮布局；原生 320dp、主页面/子页视觉和返回路径仍需设备验收，JS bundle 和组件交互测试不能替代。
