# 知行 Next

面向本人日常使用的个人助手，使用 React Native、Expo、Python、SQLite 与 Deep Agents / LangGraph。

2026-10-23 源码增加[人格成长与主动服务](docs/MUSE-GROWTH.md)：保留 Muse 的“拥有灵魂、像人一样成长”人格表达，单独保存演化人格、方法经验、主动消息偏好和目标跟进。worker 心跳维护有来源的个性化理解，并在开启主动消息后按偏好将有用的跟进送入已有聊天；默认静默维护，主动消息需启用。该机制已在 2026-10-24 独立部署至 schema v15，真实模型核心场景通过；措辞质量与手机通知边界见验收记录，没有接入远程推送。

源码中的主知行可将独立问题交给有界只读研究子 Agent，追加要求并收齐结果；也可向已有对话发起持久只读咨询，等待期间释放聊天执行槽。转发来源、取消和重启状态保留真实回执，服务写入继续走用户所在对话及固定服务助手。工具契约与模型调用体验评测见 [Agent 协作说明](docs/AGENT-COLLABORATION.md)，发布与部署状态另行验收。

当前源码的手机入口为“首页、生活、知行、施工中、设置”。财务和健康归属生活页，进入后作为子页面使用，返回生活页；原工作位置保留为“施工中”，功能待定。主知行与固定财务、健康子 Agent 共用真实服务数据：可以聊天或直接记录收支、饮食和体重，修改预算、身体限制与饮食规范，再查看预算、选择下一餐和回顾。收入、目标与规范均为运行时配置，不预置个人数字。主／子 Agent 复用历史、记忆、附件、计算、日期与报告交付能力；预算修改保留未改字段，季度支付与月成本分开，不确定日期保留范围。聊天里的报告附件可直接打开，也可下载分享。银行直连、自动对账、健康平台同步及远程个性化推送尚未接入。

同一句中的明确餐费与实际饮食可在一个事务内记录、关联和纠正。旧工作功能、项目管理、任务模式和通用计划入口已移除；施工页不提供这些操作。历史与聊天运行底座保留，数据库 v12 迁移会停用已有通用计划。附件、记忆、供应商设置和主／子 Agent 对话继续使用原链路。

本机健康提醒滚动安排未来 14 天，每次同步按当前规则更新；“今天不提醒这台手机”可离线取消当天排期。权限、系统限制和长期不打开 App 会影响提醒。本次按用户要求完成 Android 模拟器原生验收，已观察到退出后实际通知与点击跳转；投递可能延迟，实体手机与厂商电池策略未覆盖。

后续正式发版由 GitHub Actions 在推送正式版本标签时执行检查、签名构建和 Release 附件发布，普通提交和 PR 不消耗 Actions 运行时间；日常验证在本地完成。流程见[GitHub 发布](docs/DEPLOYMENT.md#客户端-github-发布)。设置中的“检查更新”优先使用官方发布附件清单，以公开 GitHub API 备用，并保留本机已核验缓存；断网显示缓存核验时间并保留下载入口，无需连接知行服务。Android 下载与安装入口在 App 内，系统仍需用户确认。

首页新增位置天气、只读今日日程与财务／健康速览，手机信息按需授权，时间跟随手机时钟。“开始”只追加到可编辑的主 Agent 草稿；新增收支优先进入财务 AI，不自动发送模板，手动补记与已有记录纠正仍保留。具体使用与验证见[今天首页说明](docs/TODAY-HOME.md)。

“设置 → 工具箱 → 密码管理”支持网站／网址、账号、密码及辅助邮箱、电话、密保问题、自定义字段。使用独立主密码，仅本机加密保存，不进入 AI；离开、后台或闲置会锁定，复制内容按持有关系尝试限时清理。主密码无法找回，卸载会丢失密码库。Android 密码库要求 API 26 起，使用和验证边界见[本机密码管理](docs/PASSWORD-VAULT.md)。

## 本地开发

聊天“添加资料”支持相册多选和文件多选，可预览、移除后批量上传并加入草稿。主知行、财务和健康共用此入口；每条消息最多 8 份附件，失败只重试剩余项。新增原生照片选择依赖，开发调试需要重新构建 App，正式用户需安装 0.2.8 或更新版本。使用与验证边界见[照片批量上传](docs/PHOTO-UPLOADS.md)。

使用当前 Expo SDK 支持的 Node.js LTS；本仓库开发环境为 Node.js 24。依赖使用 npm 与 lockfile。

```sh
npm ci
npm start
```

`npm run android`、`npm run ios` 用于具备相应 SDK 的原生开发环境。后端按[启动说明](backend/README.md#启动)配置，手机连接可在设置中修改。正式 App 只接受不含凭据的 HTTPS 服务地址；服务令牌使用手机安全存储，模型密钥留在服务端，安装包不内置令牌或供应商密钥。

## 验证与安装包

```sh
npm run typecheck
npm run lint
npm run test:mobile
npm run bundle:android
npm run bundle:ios
npx expo-doctor
```

后端在 `backend/` 执行 `uv run pytest -q` 与 `uv run ruff check .`。`bundle:*` 只生成 JS/Hermes 产物。正式 APK 通过[签名构建脚本](scripts/build_android_release.py)生成并内嵌 JS，应用支持 Android API 24 起，密码库要求 API 26 起；本次 APK 仅包含 arm64。相同业务源码的报告预览和失败重试已完成 Android 模拟器原生验收；本轮 Actions 正式包的构建、覆盖安装、检查更新和下载校验另行记录，见[0.2.6 发布说明](docs/RELEASE-0.2.6.md)。首页与密码库的既有验收见[0.2.2 说明](docs/RELEASE-0.2.2.md)，完整业务与通知见[0.2.0 说明](docs/RELEASE-0.2.0.md)。实体 Android 手机和原生 iOS 未覆盖；iOS JS bundle 不等于 iPhone 安装包。
